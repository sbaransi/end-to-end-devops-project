# Terraform: the "builder" EC2 instance

This folder creates the AWS server used to build and run the Flask AWS monitoring app.

## What it creates (us-east-1)

| Resource | Details |
|---|---|
| EC2 instance `builder` | Amazon Linux 2023, `t3.micro` (free tier), public IP, 20 GB disk |
| SSH key pair `builder-key` | Generated by Terraform. The private key is saved as `terraform/builder_key.pem` (mode 0600, ignored by Git). Only the public key goes to AWS |
| Security group `builder-sg` | Inbound **22 (SSH)** and **5001 (app)** only from your current public IP (`/32`). All outbound allowed |
| Docker + Docker Compose | Installed automatically on first boot by `user_data.sh` (no manual steps) |

No VPC is created. By default the account's **default VPC** and its public subnet in `us-east-1a` are used.
In the college lab account set `vpc_id = "vpc-044604d0bfb707142"` and a public `subnet_id` (see `terraform.tfvars.example`).

## Files

| File | Purpose |
|---|---|
| `versions.tf` | Terraform and provider versions, AWS region |
| `variables.tf` | Settings you can change (region, instance type, VPC, subnet, allowed IP) |
| `main.tf` | VPC/subnet lookup, AMI, SSH key, security group, EC2 instance |
| `user_data.sh` | First-boot script: installs Docker, Docker Compose and Git, adds `ec2-user` to the `docker` group |
| `outputs.tf` | Public IP, security group ID, SSH key path and name, ready-to-use SSH command and app URL |

## Prerequisites

- Terraform 1.5 or newer (`terraform version`)
- AWS CLI logged in to your account (`aws sts get-caller-identity` works)

## Run it

```bash
cd terraform
terraform init       # download the providers
terraform plan       # preview: 5 resources to add
terraform apply      # type "yes"
terraform output     # show the results
```

## Verify

```bash
# 1. SSH into the instance (the command is printed by "terraform output ssh_command")
ssh -i builder_key.pem ec2-user@$(terraform output -raw public_ip)

# 2. On the instance: wait for user-data to finish, then check Docker
cloud-init status --wait
docker --version
docker compose version
docker run --rm hello-world
sudo cat /var/log/user-data.log     # full installation log
```

User-data runs **after** `terraform apply` finishes, so the first SSH login can come before Docker is ready.
`cloud-init status --wait` waits until it is done (about 1–2 minutes).

Security group check: from another network (for example a phone hotspot) port 22 and 5001 must **not** answer.

## Clean up (avoid charges)

```bash
terraform destroy    # type "yes"
```

Destroy the instance when you are not using it. A stopped or forgotten instance and its disk can cost money outside the free tier.

## Notes

- The exam text offers a `remote-exec` provisioner as the automated option. The instructor asked for **user-data**, which is used here:
  AWS runs the script on first boot, Terraform does not need an SSH connection.
- Your public IP is found automatically with `https://checkip.amazonaws.com`. If your IP changes (another Wi-Fi, VPN),
  run `terraform apply` again to update the security group.
- `terraform.tfstate` stays on your laptop and is ignored by Git. The `tls_private_key` resource (from the exam example) keeps the
  private key in the state file, so the state must never be shared. Alternative without the key in state: create the key with
  `ssh-keygen` and pass only the public key to `aws_key_pair`.
